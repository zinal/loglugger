# История изменений

Все значимые изменения проекта фиксируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

English version: [CHANGELOG.md](CHANGELOG.md).

## [Unreleased]

Обзорные изменения в ветке `main` относительно тега `v1.0`.

### Изменено

- Семантика доставки в документации описана как **at-least-once** (с упорядоченной обработкой на клиента), вместо прежней формулировки exactly-once.
- Лимит размера клиентского пакета считается по точной длине несжатого JSON-тела запроса (по умолчанию **15 MiB**), а не по приближённому бюджету несжатых log-данных.
- Лимит сжатого тела запроса на сервере по умолчанию увеличен с 8 MiB до **16 MiB** и согласован с JSON-лимитом клиента и существующим лимитом 32 MiB после распаковки.
- Инструментарий Go обновлён с 1.24.x до **1.26.5**.

### Добавлено

- Файл `AGENTS.md` с требованием синхронно обновлять `CHANGELOG.md` и `CHANGELOG-ru.md` при существенных изменениях.
- Настраиваемые таймауты HTTP-сервера (`read_header_timeout`, `read_timeout`, `write_timeout`, `idle_timeout`) для защиты от Slowloris и «зависших» соединений.
- Поведение fail-stop у клиента при неретраируемых HTTP-ошибках отправки пакета (4xx, кроме обрабатываемого несовпадения позиции) и при устойчивых ошибках чтения journald после короткого окна повторов (~15 с).
- Более строгий resume из journald: сохранённые курсоры проверяются через `sd_journal_test_cursor`, поэтому vacuum/ротация журнала приводит к reset, а не к пропуску записей.
- Сервер отвечает **HTTP 400**, если сопоставление полей или transform для записи в пакете завершились ошибкой (позиция не продвигается).
- Валидация конфигурации клиента для параметров batch/HTTP-таймингов и отклонение учётных данных, встроенных в URL серверов.
- В Ansible-примере пароли статической аутентификации YDB можно хранить в **Ansible Vault**; конфигурация сервера устанавливается с правами `0600`.
- Ansible-роли перезапускают сервисы Loglugger при замене установленных бинарных файлов.

### Исправлено

- Экстрактор больше не использует автоматический retry YDB SDK вокруг callback выгрузки в файлы (из‑за него после transient-ошибки в TSV могли дублироваться строки). Transient-сбои повторяются вручную с явным логированием после удаления существующих файлов `<output-prefix>_*.tsv[.zst]`, поэтому тот же запуск можно повторить и после неудачной выгрузки.
- После HTTP `409` из‑за несовпадения позиции, если не удались и seek к `expected_position`, и fallback seek к началу journal, клиент завершает работу (fail-stop), а не продолжает с `streamRestarted` из неперепозиционированного journal.
- После успешного восстановления после повреждения journal клиент сохраняет и отправляет уже накопленные неотправенные записи batcher (и незавершённое multiline-состояние) с `reset: true`, вместо их очистки. Восстановление продолжается после последнего прочитанного cursor, поэтому сброс буфера мог безвозвратно потерять записи, которые journald больше не отдаст.
- После HTTP `409` из‑за несовпадения позиции (reseek/reset) клиент сбрасывает неотправенный остаток batcher и незавершённое multiline-состояние, оставшиеся после JSON/count-split, чтобы устаревшие `current_position` не вызывали повторные `409` и не портили reset-пакет.
- Клиент больше не уходит в busy-poll при непрерывном потоке journald; ошибки `GetEntry`, не связанные с повреждением, пропускаются без обхода путей восстановления.
- Непрерывность позиции сохраняется при `message_regex_no_match: skip` (отброшенные записи не двигают протокольные позиции).
- Ответы HTTP `409` с некорректным JSON-телом больше не считаются успешной приёмкой пакета.
- Запись в YDB кодирует значения по актуальным типам колонок таблицы (`DescribeTable`), корректно оборачивает присутствующие nullable-значения как optional и сохраняет `seqno` / `ts_orig` позиции, если пакет их не передаёт.
- Построение YDB DSN и пути таблиц для native API корректно обрабатывают абсолютные пути базы (без double-slash и усечённых путей).
- Создание выходных файлов экстрактора усилено; документация по экранированию TSV соответствует реализации (`\t` / `\n` / `\r`).
- Финальная отправка пакета при shutdown ограничена коротким таймаутом, чтобы процесс не зависал при выходе.
- HTTP-sender клиента ограничивает объём чтения тел ответов/ошибок в память.
- Обновлены примеры и спецификация: gzip `Content-Encoding` для batch POST, периодический reshuffle нескольких endpoint’ов, ожидания по уникальности `client_id`, а также примеры развёртывания ydbd.

### Безопасность

- Ansible-пример больше не предполагает хранение пароля YDB открытым текстом в inventory; учётные данные перенесены в зашифрованный Vault-файл, а конфигурация сервера ставится с ограниченными правами.
